# Nubis 사용자 가이드

Nubis 는 클라우드 서버를 프로필별로 모아 SSH · RDP · SFTP 로 접속하고, 앱 안의 Claude 에게 말로 서버 점검과 설정을 맡기는 Windows 원격 접속 클라이언트입니다. 이 문서는 설치부터 모든 기능과 설정의 동작까지 설명합니다.

## 1. 시작하기

### 1.1 요구 사항

| 항목 | 내용 |
|---|---|
| OS | Windows 10 / 11 (64비트) |
| 런타임 | 필요 없음 — 배포용 exe 는 .NET 을 포함한 단일 파일 |
| WebView2 | Windows 10/11 에 기본 포함 (터미널 화면에 사용) |
| Claude 패널 (선택) | [Claude Code CLI](https://docs.claude.com/claude-code) — `npm install -g @anthropic-ai/claude-code` |
| 클라우드 가져오기 (선택) | 쓰는 클라우드의 CLI 로그인 (`aws`, `tccli`, `gcloud`, `az`) |

### 1.2 설치

1. 배포 zip(`Nubis-<버전>-portable-win-x64.zip`)을 원하는 폴더에 풉니다.
2. 폴더 안의 `Nubis.exe` 를 실행합니다. `wwwroot\` 폴더는 터미널 화면에 쓰이므로 exe 와 같은 폴더에 둡니다.
3. 소스로 직접 빌드하려면 저장소에서 `.\build.ps1 publish` 를 실행합니다 (`publish\Nubis.exe` 생성).

설치 프로그램이 없는 포터블 앱입니다. 사용자 데이터는 exe 폴더가 아니라 `%APPDATA%\Nubis` 에 저장되므로, 새 버전은 exe 만 바꾸면 됩니다.

> **주의** 이 버전부터 데이터 파일이 암호화됩니다. 새 버전으로 한 번 실행한 뒤에는 0.1.x 버전으로 돌아가지 마세요 (암호화된 파일을 읽지 못해 빈 목록으로 시작합니다).

### 1.3 첫 실행

1. **언어 선택** — 한국어(기본) 또는 English. 한 번만 묻고, 이후에는 [Settings → 언어](#111-언어)에서 바꿉니다.
2. **시작 화면 로그인** — 설정한 경우에만 나옵니다 ([10장](#10-시작-화면-로그인과-계정별-프로필)).
3. **시작하기 안내** — 메인 화면이 열린 뒤 한 번 자동으로 뜹니다. 카드마다 두 가지 버튼이 있습니다.
   - 왼쪽 버튼(예: "새 호스트", "Cloud 열기"): 그 기능의 화면으로 바로 이동합니다.
   - **Claude 에게 묻기**: 오른쪽 Claude 패널을 열고 안내 질문으로 대화를 시작합니다. Claude 가 현재 설정 상태를 확인하고 필요한 화면을 열어 가며 한 단계씩 안내합니다.

   안내는 Settings 의 **시작하기 안내 다시 보기** 로 언제든 다시 열 수 있습니다.

처음에 무엇부터 할지 모르겠다면: 클라우드를 쓰면 [클라우드 가져오기](#8-클라우드-서버-가져오기), 아니면 [호스트 직접 추가](#31-호스트-추가)부터 시작하세요.

## 3. 호스트 관리

### 3.1 호스트 추가

**NEW HOST** 를 누르면 편집 패널이 열립니다.

| 항목 | 설명 |
|---|---|
| 프로토콜 | SSH 또는 RDP. 바꾸면 포트가 기본 포트로 바뀝니다 |
| 주소 · 포트 | IP 또는 호스트명. 포트 기본값은 [Settings → 기본 포트](#115-기본-포트) |
| 공인 IP (선택) | EIP 등. "공인 IP 로 접속" 을 켜면 이 주소로 접속 |
| 이름 | 카드에 보이는 이름 (비우면 주소) |
| 그룹 | 카드를 묶는 이름 (예: Production) |
| 로그인 계정 | [Vault](#7-vault--공용-계정) 계정을 고르면 그 사용자명·비밀번호·키로 접속 |
| 사용자명 · 비밀번호 | 직접 입력. Vault 를 골랐다면 **비워 두면 Vault 값, 적으면 이 값이 우선** |
| 개인키 파일 (SSH) | OpenSSH / PuTTY(.ppk) / PEM 키 파일. 키 암호는 비밀번호 칸 값으로 시도 |

**저장** 또는 **저장 후 연결** 을 누릅니다. 비밀번호는 Windows DPAPI 로 암호화되어 저장됩니다.

### 3.2 접속과 빠른 접속

- **카드 더블클릭** — 접속. 우클릭: 연결 · 공인/사설 IP 로 연결 · 편집 · 복제 · 삭제
- **빠른 접속** — 검색창에 `user@host[:port]`(SSH) 또는 `rdp host[:port]` 를 입력하고 Enter. 목록에 저장되지 않습니다
- **명령줄** — `Nubis.exe --connect "호스트 이름"` 으로 시작하면서 접속 (여러 번 지정 가능), `--claude` 는 Claude 패널을 연 채로 시작
- 계정이 없으면 접속할 때 묻고, "저장" 을 체크하면 로그인에 성공한 계정만 저장합니다

### 3.3 사설 IP · 공인 IP

호스트는 사설 IP(기본 접속 주소)와 공인 IP 를 함께 가질 수 있습니다. 기본은 사설 IP 로 접속하고, 호스트 편집의 "공인 IP 로 접속" 또는 카드 우클릭으로 바꿉니다. Claude 의 여러 서버 명령 실행은 사설 → 공인 순서로 시도합니다 (연결 실패일 때만 다음 주소로, 인증 실패는 바로 중단).

## 4. SSH 터미널

| 동작 | 방법 |
|---|---|
| 복사 | 드래그로 선택 후 우클릭, 또는 `Ctrl+Shift+C` |
| 붙여넣기 | 선택 없이 우클릭, `Ctrl+Shift+V`, `Shift+Insert` |
| 재연결 | 연결이 끊긴 탭에서 Enter |
| 탭 전환 | `Ctrl+Tab` / `Ctrl+Shift+Tab` (터미널에 포커스가 있어도 동작) |

- **호스트키** — 처음 접속하는 서버의 키는 저장 후 신뢰합니다 (Settings 에서 확인 창을 켤 수 있음). **저장된 키와 다르면 항상 경고**합니다. 서버를 재설치해 키가 바뀌었다면 [Known Hosts](#122-known-hosts) 에서 지우고 다시 접속하세요.
- **테마 · 글꼴 · 구문 강조** — [Settings → 터미널](#112-터미널) 에서. 열린 터미널에 바로 적용됩니다.

## 5. SFTP 파일 전송

SSH 로그인에 성공하면 왼쪽에 SFTP 패널이 자동으로 붙습니다. 터미널이 로그인한 계정으로 별도 SFTP 연결을 엽니다. 도구 막대의 폴더 버튼으로 열고 닫고, 경계선을 끌어 폭을 조절합니다.

### 5.1 탐색

- 경로를 직접 입력하거나 폴더를 더블클릭. Backspace = 상위, F5 = 새로고침, 홈 버튼 = 홈 폴더
- **터미널 폴더 따라가기** — 터미널에서 `cd` 하면 패널도 그 폴더로 이동합니다. 셸이 현재 폴더를 알려줘야(OSC 7) 동작하므로, 필요하면 서버의 `~/.bashrc` 에 추가하세요:
  ```bash
  PROMPT_COMMAND='printf "\e]7;file://%s%s\a" "$HOSTNAME" "$PWD"'
  ```
  알려주지 않는 셸이면 패널의 **터미널 아이콘** 버튼을 누르세요. 프롬프트(`user@host:/경로$`)에서 경로를 읽어 이동합니다.

### 5.2 업로드 · 다운로드

| 동작 | 방법 |
|---|---|
| 업로드 | 탐색기에서 파일·폴더를 끌어다 놓기 (폴더 행 위에 놓으면 그 폴더로), 또는 업로드 버튼 |
| 다운로드 | 항목을 탐색기·바탕화면으로 끌어내기, 또는 다운로드 버튼 → 폴더 선택 |
| 서버 간 복사 | 다른 SSH 탭의 SFTP 패널로 끌어다 놓기 (이 PC 의 임시 폴더를 거침) |

끌어내기는 마우스를 놓는 순간 받기 시작합니다. 진행률과 취소는 패널 아래에 보입니다.

### 5.3 편집하고 저장하면 서버에 반영

1. 파일을 더블클릭(또는 우클릭 → **편집**)합니다.
2. 임시 폴더로 받아 [설정한 편집기](#114-sftp)로 엽니다.
3. 편집기에서 저장할 때마다 내용이 바뀌었으면 같은 경로로 자동 업로드합니다 ("저장됨 → 서버에 올림").
4. 편집하는 동안 서버의 파일이 바뀌었으면(수정 시각·크기) 덮어쓸지 묻습니다. **아니요** 를 누르면 이번 저장은 올리지 않습니다.

> **팁** 편집기를 VS Code 로 지정하면, 그 VS Code 창의 Claude Code 로 고친 내용도 저장하는 순간 서버에 올라갑니다. 운영 서버 설정 파일을 열어 둘 때는 주의하세요.

우클릭 **읽기 전용 사본 열기** 는 받아서 열기만 하고 업로드하지 않습니다.

## 6. RDP 원격 데스크톱

Windows 내장 원격 데스크톱 엔진(mstsc 와 같은 `mstscax`)을 앱 안에 띄웁니다.

- 사용자명은 `DOMAIN\user` 형식을 지원합니다
- 창 크기를 바꾸면 원격 해상도가 맞춰집니다 (Windows 8.1 / 2012 R2 이상)
- 연결 품질, 색 깊이, 화면 효과, 클립보드·프린터·드라이브·스마트카드 리디렉션, 소리, Windows 키 전달, 자동 재연결은 **mstsc 기본 설정 파일 `문서\Default.rdp`** 를 그대로 따릅니다. mstsc 에서 바꾼 기본값이 Nubis 에도 적용됩니다
- 서버 인증서 경고만 Nubis 설정을 따릅니다 ([Settings → RDP](#117-claude--rdp))
- RDP 화면에 포커스가 있으면 `Ctrl+Tab` 은 원격으로 전달됩니다 (탭을 클릭해 전환)

## 7. Vault — 공용 계정

여러 서버가 같은 계정을 쓰면 Vault 에 한 번 저장해 두고 호스트마다 골라 씁니다.

### 7.1 계정 추가

사이드바 **Vault** → **계정 추가**.

| 항목 | 설명 |
|---|---|
| 이름 | 목록에 보이는 이름 (예: 운영 서버 root) |
| 사용자명 | 호스트에 사용자명이 없을 때 쓰는 값 |
| 비밀번호 (선택) | SSH · RDP 로그인 비밀번호 |
| SSH 개인키 (선택) | 파일에서 가져오거나 내용 붙여넣기. OpenSSH · PuTTY(.ppk) · PEM |
| 키 암호 | 키에 암호가 걸려 있을 때 |

비밀번호와 키 중 하나는 있어야 합니다. 키는 저장할 때 실제로 읽어 보고 공개키를 만들어 둡니다 — **공개키 복사** 로 서버의 `~/.ssh/authorized_keys` 에 붙여넣으세요.

### 7.2 호스트에 연결

호스트 편집 → **로그인 계정** → **Vault 계정 선택**. 카드에 "사용자 root · 비밀번호 · ssh-ed25519 키" 처럼 무엇으로 로그인하는지 표시됩니다.

| 규칙 | 동작 |
|---|---|
| 우선순위 | 호스트에 직접 적은 값 > Vault 값 > (클라우드 호스트) 프로필 기본 계정 |
| RDP | 사용자명 · 비밀번호만 씀 (키 무시) |
| 값 변경 | 그 계정을 쓰는 모든 호스트에 적용 |
| 비밀번호가 바뀐 경우 | 접속할 때 새 비밀번호를 입력·저장하면 Vault 계정이 갱신됨 |
| 계정 삭제 | 쓰던 호스트에서 연결이 해제됨 (삭제 전에 목록 표시) |

## 8. 클라우드 서버 가져오기

이 PC 의 CLI 로그인 정보를 그대로 씁니다. 키를 따로 입력하지 않습니다.

### 8.1 준비

| 클라우드 | 그룹 단위 | 먼저 할 일 | 읽는 위치 |
|---|---|---|---|
| AWS | 프로필 | `aws configure` 또는 `aws sso login` | `~/.aws/config` |
| Tencent | 프로필 | `tccli configure` | `~/.tccli/<프로필>.credential` |
| GCP | 프로젝트 | `gcloud auth application-default login` | ADC 파일 |
| Azure | 구독 | `az login` | `~/.azure` |

Cloud 페이지의 각 섹션에 있는 **로그인** 버튼은 해당 CLI 로그인 명령을 새 콘솔 창에서 실행합니다. 인증 파일이 표준 위치가 아니면 **경로 변경** 으로 지정합니다.

### 8.2 가져오기

1. Cloud 페이지 → 해당 클라우드의 **프로필 추가**(GCP 는 프로젝트, Azure 는 구독)
2. 이 PC 에서 찾은 항목을 골라 추가하면 바로 동기화됩니다
3. Hosts 페이지에 클라우드 배지가 붙은 그룹으로 나타납니다

### 8.3 동기화 규칙

| 항목 | 동작 |
|---|---|
| 이름 | `Name` 태그(또는 인스턴스 이름)를 `이름:용도` 로 분리 |
| 주소 | 사설 IP 와 공인 IP 를 모두 저장. 기본 접속은 사설 IP (프로필 설정에서 공인 기본으로) |
| 프로토콜 · 포트 | Windows → RDP, 그 외 → SSH. 포트는 [기본 포트](#115-기본-포트) 또는 프로필별 지정 |
| 상태 | terminated 제외, 중지된 서버는 흐리게 (프로필 설정에서 제외 가능) |
| 다시 동기화 | 이름·주소·상태는 갱신, 사용자가 바꾼 프로토콜·포트·계정·공인 IP 사용은 유지, 사라진 서버는 제거 |
| 일부 실패 | 일부 리전 조회가 실패하면 **그 동기화에서는 삭제하지 않음** |
| 계정 | 호스트 값 → Vault → 프로필 기본 계정(프로필 설정) → 접속할 때 입력 |
| 목록에서 삭제 | 클라우드의 서버는 그대로, 다음 동기화에서도 숨김 (프로필 설정에서 해제) |

## 9. Claude 패널

타이틀바의 **✦ Claude** (또는 `Ctrl+Shift+A`) 로 오른쪽에 공식 Claude Code CLI 를 띄웁니다. 앱이 내장 MCP 서버(`127.0.0.1`, 실행마다 새 토큰)를 열고 자동으로 연결하므로, Claude 가 Nubis 를 직접 다룰 수 있습니다.

### 9.1 처음 쓸 때

1. Claude Code CLI 를 설치합니다: `npm install -g @anthropic-ai/claude-code`
2. 패널을 열면 작업 폴더(`%APPDATA%\Nubis\claude`) 신뢰를 묻습니다 — **Yes** 를 고릅니다
3. 로그인되어 있지 않으면 `/login` 을 입력합니다

### 9.2 할 수 있는 일 (예시)

| 하고 싶은 일 | 이렇게 말하기 |
|---|---|
| 접속 | "web-01 접속해줘" |
| 여러 서버 점검 | "Production 그룹 디스크 사용량 확인해줘" |
| 지금 화면 분석 | (탭을 보면서) "이 에러 뭐야?" — 보고 있는 탭이 질문마다 자동으로 전달됩니다 |
| 로그 보기 | "web-01 의 /var/log/nginx/error.log 끝부분 보여줘" |
| 접속 문제 진단 | "web-02 접속이 안 돼, 원인 찾아줘" |
| 호스트 관리 | "10.0.1.5 를 web-02 로 Production 에 추가하고 운영 계정 연결해줘" |
| 클라우드 | "AWS 프로필 다시 동기화해줘" |
| 앱 설정 | "터미널 테마 dracula 로, 글꼴 16" |
| 설정 안내 | "GitHub 로그인 설정을 단계별로 알려줘" |

### 9.3 승인과 기록

| 동작 | 승인 |
|---|---|
| 조회 (호스트 목록, 화면 읽기, 화면 캡처, 접속 진단, 설정 조회) | 없음 |
| 원격 파일 읽기 (`sftp_list`, `sftp_read`) | 승인 창 (읽기 전용 자동 승인을 켜면 생략) |
| 여러 서버 명령 실행 (`run_command`) | 승인 창 (읽기 전용 자동 승인을 켜면 조회 명령만 생략) |
| 터미널 입력, 호스트 추가·수정·삭제, 파일 업로드·다운로드 | **항상 승인 창** |
| 보안 설정 변경 (RDP 인증서 경고, 호스트키 확인 창, 자동 승인) | **승인 창**. 자동 승인은 Claude 가 켤 수 없고 끄기만 가능 |
| 시작 화면 로그인 · 편집기 경로 | Claude 가 바꿀 수 없음 |

승인 창은 대상 서버와 명령 전체를 보여 주고, 위험한 명령(`rm -rf`, `reboot`, `Stop-Service` 등)을 경고하며, 뜬 직후 1.5초 동안 실행 버튼이 잠깁니다. Esc 는 거부입니다. 모든 요청은 감사 로그(패널 헤더의 문서 아이콘)에 기록됩니다.

### 9.4 Claude 가 할 수 없는 것

- 저장된 비밀번호 · 키를 읽거나 복호화 — 계정 파일(`hosts.json`, `vault.json` 등)은 Claude 의 읽기 도구와 셸 명령에서 차단됩니다

- Nubis 데이터 폴더 · `~/.ssh` · 개인키 파일을 서버로 업로드
- 시작 화면 로그인 설정, 편집기 경로, `settings.json` 직접 수정

## 10. 시작 화면 로그인과 계정별 프로필

### 10.1 설정 (GitHub 예)

1. github.com/settings/developers → **OAuth Apps** → **New OAuth App**
   - Application name: `Nubis` (아무 이름)
   - Homepage URL · Authorization callback URL: 아무 주소 (예: `http://localhost`) — Device Flow 에서는 쓰지 않습니다
2. 만든 앱의 설정에서 **Enable Device Flow** 를 체크하고 **Client ID** 를 복사합니다 (Client Secret 은 만들지 않아도 됩니다)
3. Nubis → Settings → **시작 화면 로그인** → **GitHub**
4. Client ID 와 **허용 계정**(GitHub 로그인 이름, 쉼표로 여러 개)을 입력합니다. 조직 전체를 허용하려면 **GitHub Organization** 에 조직 이름을 넣습니다
5. **테스트 로그인 후 저장** — 화면의 코드를 브라우저에 입력해 승인하면 저장됩니다. 테스트 로그인에 성공해야만 저장되므로 잘못된 설정으로 갇히지 않습니다
6. 다시 시작하면 로그인 화면이 나옵니다

| 제공자 | 등록 위치 | 필요한 값 |
|---|---|---|
| GitHub | github.com/settings/developers → OAuth App, **Enable Device Flow** | Client ID |
| Google | Google Cloud 콘솔 → 사용자 인증 정보 → OAuth 클라이언트 ID, 유형 **TV 및 입력 제한 기기** | Client ID · Client Secret |
| Microsoft | Entra 관리 센터 → 앱 등록 → 인증 → **공용 클라이언트 흐름 허용** | 애플리케이션(클라이언트) ID, 테넌트(`organizations` 또는 회사 테넌트) |

> **팁** 시작하기 안내의 "시작 화면 로그인 (SSO)" 카드에서 **Claude 에게 묻기** 를 누르면 Claude 가 이 과정을 화면을 열어 가며 안내합니다. 값 입력과 저장은 직접 합니다.

### 10.2 로그인 동작

| 항목 | 동작 |
|---|---|
| 방식 | OAuth Device Flow — 화면의 코드를 브라우저에서 입력해 승인. 비밀번호는 브라우저에서만 입력하고 Nubis 는 받지 않음 |
| 토큰 | 계정 확인에만 쓰고 저장하지 않음 |
| 허용 | 계정 이름(대소문자 무시), `@회사.com`(도메인 전체), GitHub Organization 멤버 |
| 로그인 유지 | 시간 단위. 0 = 실행할 때마다 로그인 (최대 720) |
| 오프라인 허용 | 일 단위. 로그인 서버에 연결할 수 없을 때, 최근 로그인 기록이 기간 안이면 들어갈 수 있음 (0 = 막음, 최대 30) |
| 기록 | 마지막 로그인은 `login.json` 에 암호화. 로그인 성공·실패는 감사 로그 |

### 10.3 계정별 프로필

로그인을 쓰면 계정마다 데이터가 따로 저장됩니다: `%APPDATA%\Nubis\users\<제공자>_<계정 ID>\`.

| 따로 저장 | 공통 |
|---|---|
| 호스트, Vault, 클라우드 프로필, known_hosts, Claude 작업 폴더, 감사 로그, 화면 설정(테마·글꼴·SFTP 등) | 언어, 시작 화면 로그인 설정, 마지막 로그인 기록 |

- 다른 계정으로 로그인하면 빈 상태로 시작하고, 서로의 데이터가 보이지 않습니다
- 계정 ID 는 바뀌지 않는 값(GitHub 사용자 번호, Google `sub`, Microsoft `oid`)이라 아이디를 바꿔도 같은 프로필이 열립니다
- **소유자** = 로그인을 설정한 계정. 로그인을 켜기 전의 데이터는 소유자가 처음 로그인할 때 넘겨받습니다. 로그인 설정은 소유자만 바꿀 수 있습니다. 로그인을 끄면 소유자의 프로필을 그대로 씁니다

### 10.4 로그인을 끄거나 잠겼을 때

- 끄기: Settings → 시작 화면 로그인 → **사용 안 함** → **저장 (로그인 끄기)** (소유자만)
- 설정이 잘못되어 들어갈 수 없으면 `%APPDATA%\Nubis\settings.json` 을 메모장으로 열어 `"Login"` 안의 `"Provider"` 를 `"None"` 으로 바꾸고 저장합니다

[10장](#10-시작-화면-로그인과-계정별-프로필) 참고. 테스트 로그인에 성공해야 저장되며, 소유자만 바꿀 수 있고, Claude 는 바꿀 수 없습니다.

### 11.7 Claude · RDP

| 설정 | 기본값 | 동작 | Claude |
|---|---|---|---|
| 읽기 전용 명령은 승인 없이 실행 | 끔 | `run_command` · `sftp_list` · `sftp_read` 중 조회 명령만 승인 창 생략 (허용 목록 방식, 애매하면 승인). 감사 로그는 남음 | 끄기만 가능 |
| RDP 서버 인증서 경고 표시 | 켬 | 끄면 인증서를 확인할 수 없는 서버(자체 서명)에도 경고 없이 접속. 다음 접속부터 적용 | 승인 필요 |

### 11.8 클라우드 인증 파일 경로

Cloud 페이지의 섹션마다 **경로 변경** 으로 지정합니다 (기본은 표준 위치). AWS 는 `AWS_CONFIG_FILE`, GCP 는 `GOOGLE_APPLICATION_CREDENTIALS`, Azure 는 `AZURE_CONFIG_DIR` 로 적용되어 로그인 버튼으로 띄우는 CLI 에도 같은 경로가 쓰입니다. Claude 는 바꿀 수 없습니다.

## 12. 데이터 파일과 보안

### 12.1 데이터 위치

| 위치 | 내용 |
|---|---|
| `%APPDATA%\Nubis\settings.json` | 언어 · 시작 화면 로그인 설정 (로그인을 쓰지 않으면 모든 설정). 평문 |
| `%APPDATA%\Nubis\login.json` | 마지막 로그인 기록 (암호화) |
| `%APPDATA%\Nubis\users\<계정>\` | 계정별 프로필 (로그인을 쓸 때) |
| `hosts.json` · `vault.json` · `cloud_profiles.json` · `known_hosts.json` | 호스트 · Vault · 클라우드 프로필 · 호스트키 (**파일 전체 암호화**) |
| `claude\` · `claude_audit.log` | Claude 패널 작업 폴더 · 감사 로그 |
| `%LOCALAPPDATA%\Nubis\WebView2\` | 터미널 화면 캐시 |

환경변수 `NUBIS_DATA_DIR` 를 지정하면 다른 폴더를 씁니다 (포터블 실행·테스트).

### 12.2 Known Hosts

사이드바 **Known Hosts** 에 신뢰한 SSH 서버의 호스트키 지문이 보입니다. 서버를 재설치해 키가 바뀌었다면 여기서 지운 뒤 다시 접속하세요. 거부한 키는 `REJECTED` 로 남아 자동 신뢰되지 않습니다.

### 12.3 보안 모델

| 보호 | 내용 |
|---|---|
| 저장 암호화 | 데이터 파일 전체를 Windows DPAPI(현재 사용자, AES-256)로 암호화. 서버 이름·IP·계정 이름도 보이지 않고, 이 PC·이 Windows 계정에서만 풀림. 비밀번호·키는 그 안에서 한 번 더 암호화 |
| 다른 PC 로 복사 | 풀 수 없음. 원본을 `*.corrupt-날짜` 로 보관하고 빈 상태로 시작 |
| 시작 화면 로그인 | 허용한 계정만 앱에 들어올 수 있고, 계정마다 데이터를 나눔 |
| Claude 패널 | 계정 파일 읽기 · DPAPI 복호화 명령 · 설정 파일 수정 차단, 원격 변경은 승인 + 감사 로그 |
| 호스트키 | 바뀐 키는 항상 경고 |

**한계** — 시작 화면 로그인과 계정별 프로필은 "앱에 들어가는 문" 과 "앱 화면에서의 분리" 입니다. 암호화는 Windows 계정 단위이므로, 같은 Windows 계정에서 도는 프로그램이 파일을 직접 푸는 것까지 막지는 못합니다. 여러 사람이 한 PC 를 쓴다면 Windows 계정을 나누세요.

### 12.4 백업과 이전

- 같은 PC · 같은 Windows 계정: `%APPDATA%\Nubis` 폴더를 통째로 복사해 두면 됩니다
- 다른 PC: 암호화 파일은 다른 PC 에서 풀리지 않습니다. 새 PC 에서 클라우드 프로필을 다시 추가해 동기화하고, Vault 계정은 다시 입력하세요

## 14. 문제 해결

| 증상 | 확인할 것 |
|---|---|
| 호스트 목록이 비어 있음 | 로그인한 계정이 다른 계정인지 (계정별 프로필). Settings 의 로그인 영역에 현재 프로필이 표시됩니다. 이전 버전으로 실행하지 않았는지 |
| "설정 파일을 읽지 못했습니다" | 다른 PC 에서 복사한 파일이거나 손상된 파일. 원본은 `*.corrupt-날짜` 로 보관됨 |
| 호스트키가 바뀌었다는 경고 | 서버를 재설치했다면 Known Hosts 에서 지우고 다시 접속. 아니라면 중간자 공격일 수 있으니 접속하지 마세요 |
| SFTP 패널이 터미널 폴더를 따라가지 않음 | 서버 셸이 OSC 7 을 보내는지 ([5.1](#51-탐색)). 패널의 터미널 아이콘 버튼으로 이동 |
| 편집한 파일이 서버에 안 올라감 | 패널 아래 상태 문구 확인. 서버 파일이 바뀌어 "아니요" 를 골랐거나 권한이 없을 수 있음. 다시 저장하면 재시도 |
| Claude 패널에 "claude 를 찾을 수 없습니다" | `npm install -g @anthropic-ai/claude-code` 후 패널의 다시 시작 버튼 |
| Claude 가 다른 탭을 봄 | 보고 있는 탭은 질문마다 자동 전달됩니다. 탭을 바꾼 뒤 새 메시지를 보내세요 |
| 클라우드 동기화 실패 | 해당 CLI 로 다시 로그인 (섹션의 로그인 버튼), 인증 파일 경로 확인. Claude 에게 "클라우드 동기화가 안 돼" 라고 물으면 상태를 확인해 줍니다 |
| 로그인 화면에서 "Client ID 에 해당하는 OAuth 앱을 찾을 수 없습니다" | Client ID 오타, GitHub 앱의 Enable Device Flow 체크 확인 |
| 로그인 설정을 잘못해 들어갈 수 없음 | [10.4](#104-로그인을-끄거나-잠겼을-때) |
| RDP 연결 직후 인증서 경고 | 자체 서명 인증서 환경이면 Settings → RDP 의 인증서 경고를 끔 |
